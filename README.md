# 공동교육과정 차량 운행 계산

부산 학교 위치를 바탕으로 공동교육과정의 하루 이동을 설계하는 로컬 웹 시연 프로그램입니다. 학생 왕복·연속 수업 이동, 다차종 전기차 배정, 제조 배분량과 운행 배출량 비교를 지원합니다.

## 실행

Python 3.10 이상이면 별도 패키지 설치 없이 실행됩니다.

```powershell
python app.py
```

Windows에서는 `./run.ps1`로도 실행할 수 있습니다. 이 실행기는 설치된 Codex 번들 Python을 우선 사용하고, 없으면 시스템 Python을 사용합니다.

브라우저에서 **http://127.0.0.1:8765**를 엽니다. 포트 변경: `python app.py --port 8766`.

## 시연 순서

1. 첫 화면에 부산 고등학교 22곳과 이동 학생 1,000명의 가상 수요가 준비됩니다.
2. **대안 계산하기**를 누릅니다. 외부 API 없이 추정 도로로 계산됩니다.
3. 저탄소·운영비·탑승시간 대안을 선택하고 차량별 경로와 시간표를 확인합니다.
4. **학교와 수요**, **차량 구성**, **계산 조건**에서 값을 바꿉니다. 변경 후에는 다시 계산해야 합니다.
5. 입력 설정 JSON, 계산 결과 JSON, 학생 이동표 CSV를 내려받을 수 있습니다. CSV 시각은 자정부터 경과한 분 단위이며 소수점은 초 미만 정밀도를 보존합니다. 화면 시각은 분 단위로 표시합니다.

학교는 제공된 `한국교육시설안전원_초중등학교위치.csv`의 부산·고등학교·운영 상태로 필터링합니다. 142개교 중 난수 seed로 22개를 선택하며, 원본은 수정하지 않습니다. 같은 좌표를 쓰는 학교도 별개 학교 ID로 유지합니다. 학교 선택, 좌표, 그룹 인원, 수업 학교와 시간은 편집할 수 있습니다.

## 카카오 연결

키는 `.local/kakao-keys.json` 파일에서만 읽습니다. 웹페이지에는 키 입력·저장 기능이 없습니다.

- `rest_key`: 카카오모빌리티 자동차 길찾기용 REST API 키.
- `js_key`: 카카오 지도 표시용 JavaScript 키. 허용 도메인에 `http://127.0.0.1:8765`를 등록합니다. localhost를 사용한다면 그 도메인도 등록합니다.

파일을 수정한 뒤 웹페이지를 새로고침하면 다시 읽습니다. 도로 조회를 시작할 때도 최신 파일을 읽으므로 서버 재시작은 필요 없습니다. 환경변수나 `.env`는 읽지 않습니다.

이 로컬 파일은 `.gitignore`로 제외하며 HTTP 경로로 제공하지 않습니다. 설정·결과 다운로드와 sessionStorage에도 키를 넣지 않습니다. JavaScript 키는 지도 SDK를 위해 브라우저에 전달됩니다.

도로 정보에서 **카카오**를 선택한 뒤 **도로 정보 준비**를 누르면 학교 간 방향별 자동차 경로를 조회합니다. 22곳은 최대 462개 구간입니다. 무료 쿼터 초과분은 사용자의 API 계정에 과금될 수 있으므로 공식 요금표를 확인하세요. 일부 구간이 실패하면 계산을 위한 새 행렬 생성을 중단하며, 실패 구간을 추정값으로 자동 대체하지 않습니다.

지도 표시와 경로 계산은 별개입니다. 지도 키만 있으면 카카오 지도 위에 추정 연결선이 표시될 수 있으며, 화면에서 이 상태를 구분합니다. 경로 키만 있으면 카카오 도로 형상을 좌표 개략도 위에 표시할 수 있습니다.

카카오 자료는 실행 중 메모리에 보관합니다. 도로 저장 버튼으로 JSON 파일을 내려받아 재사용할 수 있습니다. 자동 저장은 하지 않습니다. 학교와 좌표가 같으면 수요 재생성 시 카카오 행렬을 유지합니다. 학교가 바뀌거나 입력 설정 파일을 불러오면 카카오 재조회가 필요하다고 표시하며 추정 모드로 자동 전환하지 않습니다. 같은 탭의 입력 설정은 sessionStorage에 보관하며, 새로고침 시 학교·좌표가 맞는 기존 카카오 행렬을 재사용합니다. 키는 sessionStorage에 저장하지 않습니다. 실시간 재배차와 미래 교통 예측은 포함하지 않습니다.

카카오 키 연결 후에는 실제 경로 준비가 필요하다고 표시합니다. 조회 실패 시 기존 추정 행렬로 계산하지 않으며, 서버도 요청한 모드와 데이터 출처가 다르면 계산을 거절합니다. 화면의 `카카오 조회 필요 / 조회 중 / 조회 실패 / 실도로 연결` 상태를 확인하세요.

`네트워크 권한에 의해 차단` 오류가 나오면 제한된 에이전트 실행 환경에서 서버가 시작된 경우일 수 있습니다. 외부 네트워크가 허용된 일반 터미널에서 `run.ps1` 또는 `python app.py`로 실행해야 합니다. 방화벽이나 TLS 검증을 끄지 않습니다. 저장한 키는 서버 재시작 후에도 자동 복원됩니다.

## 이동과 차량 모델

- 하루 학생 일정은 소속 학교 → 수업 학교(여러 곳 가능) → 소속 학교입니다. 마지막 복귀를 설정으로 끌 수 있습니다.
- 다음 수업으로 이동할 때 이전 수업 종료 전에는 승차하지 않습니다. 하차 완료와 도착 여유를 포함해 다음 수업 시작 전에 도착합니다.
- 같은 학생 그룹을 고정된 학생 번호 범위로 나눕니다. 각 범위는 이동 구간마다 다른 차량에 배정될 수 있지만, 한 구간 안에서는 환승하지 않습니다.
- 차량은 학교를 반복 방문할 수 있고 학생의 수업 중 다른 운행을 할 수 있습니다.
- 각 운행 사이 이동, 거점 출발과 최종 복귀 공차를 거리·시간·배출량·배터리에 포함합니다.
- 거점은 선택한 학교 중 지정하거나 학교 간 거리 합을 기준으로 자동 선택합니다. 학교 밖 거점과 운행 중 충전 최적화는 현재 UI 범위에 포함하지 않습니다.
- 운전자 한 명을 차량 한 대에 대응시키고 기본 일일 비용에 포함합니다. 법정 근로시간·휴식·별도 기사 교대는 모델링하지 않습니다.
- 가용 배터리 전력은 하루 상한입니다. 주행 중 냉난방·고도 변화·시간 기반 공회전 부하는 별도 모델이 없으므로 사용자가 전비에 반영합니다.

## 알고리즘과 목적함수

Python 표준 라이브러리로 구현한 삽입 휴리스틱입니다. 무거운 최적화 라이브러리 없이 시연할 수 있으며, 전역 최적성을 보장하지 않습니다.

1. 수업 일정에서 승차·하차 쌍을 만듭니다.
2. 마감이 빠른 요청부터 기존 운행의 여러 위치에 넣어 봅니다. 시간창·정원·탑승 제한·거점·배터리가 맞는 후보만 남깁니다.
3. 시간 제약은 차분 부등식으로 전파하며, 불필요한 차량 내 대기를 줄이도록 승차를 늦춥니다.
4. 후보 운행에 맞는 차급을 선택합니다. 운행별 최대 사건 수, 분할 인원, 탐색 예산은 사용자가 변경할 수 있습니다.
5. 같은 차종의 운행을 실제 하루 차량으로 연결합니다. 재배치 시간과 하루 배터리 범위가 맞을 때만 재사용합니다.
6. 별도 검증기가 결과의 시간, 정원, 학생 수송, 환승 금지, 공차, 배터리를 다시 검사합니다.

탐색용 점수는 다음과 같습니다. 가중치는 **차량 구성**에서 수정할 수 있습니다.

| 대안 | 탐색 점수 |
|---|---|
| 저탄소 | 운행의 거점 왕복 포함 배출 추정 + 탄소안 시간 가중치 × 학생 탑승 명·분 |
| 운영비 | 일일 차량비/일일 운행횟수 가정 + 거점 왕복 포함 거리 변동비·전력비 |
| 탑승시간 | 학생 탑승 명·분 + 시간안 거리 가중치 × 거점 왕복 포함 km |

운행을 만들 때는 운행마다 거점 출발/복귀를 가정한 점수를 사용합니다. 최종 지표는 실제로 연결한 차량의 공차·일일 고정비를 다시 계산합니다. 따라서 이 점수는 하루 전체 최적해의 목적함수를 정확히 푸는 방식이 아닙니다. 실제 하루 결과로 탄소·비용·대기 포함 이동시간을 비교하고, 다른 안에 모든 지표가 뒤지는 안에 표시를 붙입니다.

탐색 예산을 넘기면 남은 요청은 직접 운행으로 배정합니다. 결과를 끝까지 검증한 뒤 표시하므로 설정한 개선 예산이 전체 응답시간의 엄격한 상한은 아닙니다. 차량 상한 안에서 결과를 못 찾으면 **미발견**이며 수학적으로 불가능하다는 증명은 아닙니다.

## 탄소 산정

```
제조 배분량 = 제조 총배출량 / 생애 총주행거리 × 이번 운행거리
충전 전력량 = 운행거리 × 배터리 기준 전비 / 충전효율
운행 배출량 = 충전 전력량 × 전력 배출계수
셔틀 배출량 = 모든 차량의 제조 배분량 + 운행 배출량
감축량 = 기존 이동 배출량 − 셔틀 배출량
```

차량 제조량은 배터리 포함 총량입니다. 배터리 제조를 다시 더하지 않습니다. 도로 인프라·폐기 등은 포함하지 않으므로 완전한 생애주기평가라고 부르지 않습니다.

기존 이동은 수단별 비율·경로 거리 배율·평균 탑승인원·추가 공차 비율을 사용합니다. 자동차/버스/철도의 제조·운행을 같은 범위에서 계산합니다. 수단별 평균 인원으로 학생 인·km를 차량 km로 배분한 추정이며 실제 차량 대수를 복원하는 것은 아닙니다. 혼합 수단 비율은 모집단의 기대 비율이므로 분수 인원에 해당하는 활동량도 허용됩니다.

모든 기본 차량·제조량·전비·비용·배출계수는 **시연용 가상 상수**입니다. 학교 좌표 외에는 실제 부산 학생 이동 통계로 해석할 수 없습니다. 전기차여도 기존 이동보다 배출이 많으면 증가로 표시합니다. 기존 배출이 0이면 감축률을 정의하지 않습니다. 기존 버스 승객 감소가 버스 운행 감소로 바로 이어진다고 가정하지 않습니다.

## 화면 지표

- 학생 수: 입력한 그룹 인원의 합. 기본값 1,000명.
- 명·회: 모든 학교 간 이동의 학생 수 합. 왕복이면 같은 학생을 두 번 계산합니다.
- 탑승시간: 승차 서비스 종료부터 하차 시작까지.
- 대기 포함 시간: 승차 서비스, 탑승, 하차, 수업 후 승차 대기, 다음 수업까지 조기 도착 대기를 포함. 첫 출발 전 소속 학교에서 보내는 시간은 제외.
- 기존 이동시간: 수단별 가상 거리·속도·접근/대기시간으로 계산. 실제 대중교통 시간표를 검증한 값이 아닙니다.

## 검증

```powershell
python -m unittest discover -s tests -v
node --check web/app.js
```

테스트는 데이터 인원 보존, 왕복/연속 수업, 복귀 옵션, 그룹 분할, 비대칭 도로 행렬, 정원/시간 위반 감지, 하차 완료 마감, 수요 누락, 배터리 부족, 제조·운행 산식, 공차, 음수 감축, 기준 배출 0, 카카오 응답 변환과 실패, 입력 오류, API 왕복, 다운로드, REST 키 미노출을 포함합니다.

실제 키를 이용한 카카오 호출·지도 SDK 검증은 키 연결 후 별도로 필요합니다. 현재 카카오 어댑터의 자동 테스트는 모의 응답을 사용합니다. 자동차 경로의 버스 진입 가능성을 현장 검증하지 않았습니다.

첫 출발/최종 복귀 규칙은 `make_requests`, 시간 제약은 `evaluate`, 하루 차량 재사용은 `assemble_fleet`에 모아 두었습니다. 추후 운영 규칙을 바꿀 때 수정 지점을 분리할 수 있습니다.

## 화면 모드

기본 화면은 간단 모드입니다. 학교 수·학생 수로 수요를 생성하고 도로 정보를 준비한 후 대안을 계산합니다. 상세 모드에서는 학교·수업 일정, 차종, 배출계수 등 기존의 전체 설정과 차량별 운행표를 제공합니다. 두 모드는 같은 입력과 결과를 공유하며 모드 전환으로 재계산하지 않습니다. 화면 모드 선택은 브라우저에 저장됩니다.

## 도로 및 결과 파일

운행 계획 화면의 도로 저장과 결과 저장은 각각 `roads.json`, `results.json`을 다운로드합니다. 두 화면 모드에서 사용할 수 있습니다.

- 도로 파일: 학교 좌표, 구간별 거리와 시간, 도로 형상, 데이터 출처 및 조회 시각(카카오).
- 결과 파일: 계산 당시 입력, 세 대안의 차량·운행표·탄소·비용과 당시 도로 정보. 저장 이후 변경한 입력은 포함하지 않습니다.
- 도로 불러오기: 현재 학교와 좌표, 구간 값 검증 후 외부 API 호출 없이 재사용합니다.
- 결과 불러오기: 파일의 입력과 결과로 현재 화면을 교체합니다. 재계산하지 않습니다.

파일 형식 버전은 1이며 최대 100MB입니다. 키는 포함하지 않습니다. 파일은 사용자의 브라우저 다운로드 위치에 저장되며 서버 재시작 후에도 다시 불러올 수 있습니다.

## 운행 보고서

운행 보고서 내보내기는 현재 선택한 대안의 계산 당시 학교 목록, 학생 그룹별 수업과 배차, 차량별 경로 그림과 운행표를 `transport-report.html`로 저장합니다. 인터넷이나 API 키 없이 열 수 있으며, 브라우저 인쇄 기능에서 PDF로 저장할 수 있습니다. 학생 번호는 각 그룹 내 번호입니다. 경로 그림은 도로 좌표를 그린 배경 지도 없는 도식이며, 추정 모드는 직선 연결선으로 표시합니다.

## 임시 외부 공유

`start-sharing.ps1`은 별도 공개 서버(127.0.0.1:8767)와 Cloudflare Quick Tunnel을 실행하고 HTTPS 주소를 출력합니다. 기존 로컬 서버(8765)는 유지됩니다. `.local/cloudflared.exe`는 Cloudflare 공식 Windows 실행 파일입니다. 외부 네트워크 접근이 허용된 PowerShell에서 실행합니다.

```powershell
.\start-sharing.ps1
.\stop-sharing.ps1
```

공개 서버는 카카오 신규 조회를 서버에서 차단하며 REST 키를 제공하지 않습니다. 지도용 JavaScript 키는 설정된 경우 브라우저에 전달합니다. 추정 도로 계산, 도로·결과 파일 불러오기, 저장, 보고서 내보내기를 지원합니다. 지도 키가 없으면 좌표 도식으로 표시하고 불러온 카카오 도로 형상을 그립니다. 세션은 브라우저 쿠키로 분리하고 1시간 미사용 시 만료됩니다. 최대 40개 세션과 동시 계산 2건을 허용합니다. 공유 종료나 서버 재시작 시 메모리 데이터는 사라지므로 필요한 결과는 파일로 저장합니다.

공유 주소와 프로세스 ID는 `.local/sharing.json`에 기록됩니다. 종료 스크립트는 해당 프로젝트의 공개 서버와 터널만 종료합니다. PC 종료 시 링크는 사용할 수 없고, 다시 공유하면 새 주소가 생성됩니다.

## 시나리오 시험

상세 모드의 학교와 수요에서 유리/중간/불리 수요를 생성하거나 전체 유형을 난수별로 반복 시험합니다. 학교는 고정하고 학생당 외부 수업 1회를 생성합니다. 복귀 여부, 차종, 시간 제한과 배출계수는 현재 설정을 사용합니다. 직접 이동 가능한 구간과 시간대를 우선 생성하지만 전체 배차 불가능 사례도 제외하지 않습니다.

기본 시험은 총인원과 기존 이동수단 비율을 유지합니다. 총인원 변경 옵션은 유리 100%, 중간 50%, 불리 10%를 적용합니다. 비율 변경 옵션은 자가용/버스/철도 비율을 각각 70/20/10%, 30/50/20%, 5/25/70%로 적용합니다. 이 두 옵션은 실제 관측치가 아닌 명시적인 민감도 가정입니다.

유형별 1~3회 시험하며 각 사례의 세 대안 중 배출량이 가장 작은 실행 가능안을 비교합니다. 최선과 최악은 시험한 사례의 학생 1명당 감축량 최대/최소입니다. 전역 최적해나 확률적 신뢰구간이 아닙니다. 경로 개선 예산은 대안당 최대 1초이며 이후 직접 배정은 계속합니다. 같은 난수는 같은 입력을 생성하지만 시간 제한 휴리스틱의 출력은 실행 환경에 따라 달라질 수 있습니다.

결과 적용은 해당 입력, 도로, 계산 결과를 화면에 복원합니다. 기존 결과 저장과 운행 보고서 내보내기도 사용할 수 있습니다. 시험 결과 저장은 전체 사례 및 조건을 별도 JSON으로 내보냅니다.

## 그룹 인원 분포

새 수요 생성은 기본 1~40명 범위에서 그룹 크기를 무작위 배정합니다. 상세 모드에서 그룹 최소/최대 인원을 변경할 수 있고 총인원은 정확히 보존합니다. 범위 내 분할이 불가능한 입력은 오류로 반환합니다. 유리/중간/불리 시험은 같은 범위에서 큰 그룹 우선/균등 추출/작은 그룹 우선 가중치를 사용합니다. 난수가 같으면 같은 수요가 생성됩니다. 학생 그룹 표에는 1명 그룹 수와 실제 최소/최대 인원을 표시합니다. 기존 파일의 학생 그룹은 그대로 유지하고, 새 범위 필드가 없는 예전 API 입력의 수요 생성은 기존 고정 크기 방식을 유지합니다.

공개 테스트 서버는 시작 시 프로젝트 루트의 `roads_test.json`을 읽습니다. 새 세션에는 해당 도로 행렬이 기본 적용되고 첫 화면의 학교 및 가상 수요도 파일의 학교에 맞춥니다. 파일 변경은 공개 서버 재시작 후 새 세션부터 적용됩니다. 기존 세션에서 사용자가 불러오거나 변경한 도로는 다른 접속자에게 영향을 주지 않습니다. 로컬 서버의 도로 조회 동작은 유지합니다.

## 공개 서버 배경 지도

Render의 Environment에 `KAKAO_JS_KEY`를 지도용 JavaScript 키로 설정합니다. 로컬 공개 서버는 환경변수가 없으면 `.local/kakao-keys.json`의 `js_key`를 사용합니다. JavaScript 키는 지도 SDK를 위해 브라우저에 전달되며 REST 키와 길찾기 신규 조회는 공개 서버에서 차단됩니다.

카카오 JavaScript SDK 허용 도메인에 실제 접속 주소를 등록해야 합니다. `http://127.0.0.1:8765`와 `http://localhost:8765`는 서로 다른 주소이며 Render 주소 `https://co2-contest.onrender.com`도 별도로 등록합니다.
